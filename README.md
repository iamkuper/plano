# Plano

Канбан-доски задач для команд. Мультитенантный: у каждой компании своё рабочее пространство.

## Стек

- `apps/api`: NestJS 10 + Prisma 5 + PostgreSQL, порт 3101
- `apps/web`: Next.js 14 (App Router) + Tailwind 3, порт 3100
- `packages/shared`: общие типы, права (`PERMISSIONS`, `can`), константы — собирается в `dist`

## Запуск

```bash
./scripts/cloud-setup.sh   # зависимости, .env, Postgres на :5433, миграции, тестовые пользователи
pnpm api:dev               # http://localhost:3101
pnpm web:dev               # http://localhost:3100
```

Postgres встроенный (`embedded-postgres`, данные в `apps/api/.pgdata`), Docker не нужен.
Остановить: `pnpm db:down`. Тестовые пользователи и пароли — в `apps/api/.env.example`.
Новое рабочее пространство создаётся на `/register`: компания + её первый администратор.

## Модель

Проект → Доска → Колонки (последняя = «Готово») → Карточки (чек-лист, сообщения,
вложения, учёт времени, история). Повторяющиеся задачи создают карточки по расписанию.
Роли: встроенный «Администратор» (может всё) и свои роли с набором прав
(Настройки → Права).

## Мультитенантность

Общая база, у верхних сущностей (`User`, `Project`, `Card`, `Template`, `Role`) есть `workspaceId`,
остальное достаётся через них. Изоляция — в `apps/api/src/prisma/tenant.ts`: `PrismaService` (его
получают все сервисы) ограничивает любой запрос рабочим пространством текущего пользователя и падает
без контекста. Для логина, планировщика повторяющихся задач и подписанных ссылок на файлы есть
`SystemPrismaService` без ограничений. Проверка изоляции на запущенном API: `node apps/api/test/isolation.mjs`.
Почта пользователя уникальна глобально: аккаунт принадлежит одному пространству.

## Тарифы и оплата

Free (3 пользователя, 3 проекта, 1 ГБ), Pro (490 ₽ за пользователя в месяц) и Business (990 ₽). Год стоит 10 месяцев.
Новое пространство получает 14 дней Pro без карты, потом Free. Лимиты и цены лежат в таблице `Plan`
(меняются миграцией или в базе). Сервер проверяет лимиты через `BillingService.assertWithin / assertFeature`
(ответ 402), существующие данные при превышении не трогаются.

Оплата — эквайринг Т-Банка (`apps/api/src/billing`). Первый платёж на странице банка с сохранением карты,
дальше автосписания по `RebillId` (проверка раз в 10 минут, 3 попытки с интервалом сутки, потом Free).
Уведомления банка: `POST /billing/webhooks/tbank`, подпись `Token` проверяется. Боевой терминал подключается
переменными `TBANK_*` (см. `apps/api/.env.example`), без них работает встроенный тестовый провайдер:
страница `/billing/mock-pay` вместо формы банка. Проверка: `cd apps/api && pnpm exec ts-node --transpile-only test/billing.ts`
(нужен запущенный API).

## Приглашения и сброс пароля

Администратор приглашает по почте (Настройки → Сотрудники → «Пригласить»): создаётся одноразовая ссылка на 7 дней,
человек сам задаёт имя и пароль и попадает в то же пространство (проверяется лимит пользователей тарифа).
«Забыли пароль?» на входе присылает ссылку на 1 час. В базе хранятся только хэши токенов.
Письма уходят по SMTP (`SMTP_*`, `MAIL_FROM`, `APP_URL`), без настройки пишутся в лог API, а ссылку-приглашение
администратор видит в интерфейсе и может передать сам. Проверка: `cd apps/api && pnpm exec ts-node --transpile-only test/invitations.ts`.

## Метки, поиск и календарь

Метки задаются в пространстве (цвет — ключ из `LABEL_COLORS`, в вебе токены `labelColor`). Любой сотрудник создаёт и
назначает метки в карточке, менять и удалять их можно с правом «Менять и удалять метки». На доске: поиск по названию,
описанию и ключу, фильтр по меткам. Вид «Календарь» показывает карточки по срокам, перетаскивание меняет срок.

## Напоминания о сроках и письма

Раз в час (`DueRemindersService`) исполнители открытых карточек получают уведомление, когда срок сегодня или завтра
(`DUE_SOON`) и на следующий день после просрочки (`OVERDUE`). Одно напоминание на карточку, человека и дату срока
(уникальный индекс), поэтому перезапуски не дублируют. Карточки в последней колонке и неактивные проекты пропускаются.
Копии уведомлений (назначение, упоминание, сообщение, срок) уходят на почту, если задан SMTP и сотрудник не отключил
письма в профиле. Проверка: `cd apps/api && pnpm exec ts-node --transpile-only test/reminders.ts`.

## Диаграмма Ганта (Business)

Вид проекта «Гант»: полосы от «Начала» до «Срока» карточки (поле «Начало» есть на всех тарифах), перенос и растягивание
мышью, масштаб дни/недели/месяцы, линия «сегодня». Связи «сначала эта, потом та» (`CardDependency`, только внутри проекта,
циклы запрещены) создаются перетаскиванием точки справа от полосы на зависимую задачу; стрелка красная, если зависимая
начинается раньше окончания предшественницы. Сервер: `GET /projects/:id/dependencies`, `POST/DELETE /cards/:id/dependencies`
(тариф с функцией `gantt`, 402 иначе). Проверка: `cd apps/api && pnpm exec ts-node --transpile-only test/gantt.ts`.

## Дополнительные поля карточек (Business)

Настройки → «Поля»: до 20 полей на пространство, типы «Текст», «Число», «Дата», «Список», «Флажок» (право
`fields.manage`). Значения (`CardFieldValue.value`, JSON) проверяются по типу поля и задаются в карточке. Создавать поля и
менять значения можно на тарифе с функцией `fields`; после понижения тарифа уже заполненное остаётся видно, правки
закрыты (402). Сервер: `GET/POST/PATCH/DELETE /fields`, `PUT /cards/:id/fields/:fieldId`.
Проверка: `cd apps/api && pnpm exec ts-node --transpile-only test/fields.ts`.

## Экспорт CSV и журнал действий (Business)

Кнопка выгрузки в шапке проекта скачивает карточки в CSV (`;`, UTF-8 с BOM, формулы нейтрализуются): ключ, название,
описание, колонка, приоритет, исполнители, метки, начало, срок, оценка, списанное время, подзадачи, дата создания и
все дополнительные поля. Журнал (Настройки → «Журнал», право `audit.view`) показывает, кто создал, изменил или удалил
проекты, сотрудников, роли, шаблоны, поля, метки, настройки, карточки и какие были платежи. Записи ведутся на любом тарифе,
читать их можно на Business. Новое действие записывается через `AuditService.record(action, summary)`.
Проверка: `cd apps/api && pnpm exec ts-node --transpile-only test/audit-export.ts`.

## Блокировка по окончании тарифа

Через 3 дня после конца оплаченного периода (или триала) пространство переходит в режим «только чтение»: все `GET`-запросы, оплата (`/billing*`), вход и профиль работают, остальные изменения сервер отклоняет кодом 402 `WORKSPACE_LOCKED`. В вебе сверху показывается плашка со ссылкой на оплату. Выйти из блокировки можно оплатой или переходом на бесплатный тариф (`POST /billing/free`). Фоновые задачи (повторяющиеся карточки, напоминания) для заблокированных пространств не выполняются.

## Онбординг

После регистрации открывается приветствие и карточка «Начало работы» на главной. Шаги определяются по реальным данным (проект, карточка, исполнитель и срок, приглашение, сообщение), а не по кликам. Онбординг можно закрыть («Не нужно, закрыть» или ×); состояние хранится на сервере по пользователю. Вернуть: Профиль → «Показать начало работы». Кнопка «Создать пример проекта» наполняет пространство демо-данными.

## Скрытая админка владельца

Страница `/platform` без ссылок в интерфейсе. Доступ у почт из `PLATFORM_ADMIN_EMAILS` (через запятую); всем остальным API отвечает 404, веб возвращает на главную. Показывает сводку, пространства с поиском и фильтрами по состоянию, позволяет выдать тариф, продлить триал, заблокировать или перевести на бесплатный (в журнале — записи `platform.*`).

## Тесты

- API: `pnpm --filter @plano/api test` (Jest + supertest, отдельная база `kanban_test`), покрытие — `test:cov`.
- Веб: `pnpm --filter @plano/web test` (Vitest + Testing Library), покрытие — `test:cov`.
- E2E: `pnpm --filter @plano/web e2e` (Playwright; сам собирает и запускает API на :3201 и веб на :3200 с базой `kanban_e2e`, платежи через mock-провайдер).

Для боевой БД нужна UTF-8 локаль (в встроенном Postgres локаль «C», поиск по кириллице без учёта регистра обеспечивает `caseVariants`).

## Тестовый терминал Т-Банка

Ключи задаются только в `apps/api/.env` (`TBANK_TERMINAL_KEY`, `TBANK_PASSWORD`) и в репозиторий не попадают. Без них работает mock-провайдер. Для вызова реального API исходящий доступ должен разрешать `securepay.tinkoff.ru`, а для уведомлений нужен публичный `API_PUBLIC_URL`.

## Языки интерфейса

Интерфейс, ответы сервера и письма доступны на русском и английском. Тексты хранятся в `packages/shared/src/locales/ru.json` и `en.json` (один каталог для веба и API). Язык выбирают на страницах входа/регистрации и в профиле; выбор сохраняется в аккаунте (`User.locale`), по нему же выбирается язык писем. Новое пространство получает стартовые данные (шаблон «Знакомство с Plano», этапы) на языке регистрации. Добавить язык: новый файл каталога, запись в `LOCALES` (`packages/shared`), перевод стартового шаблона в `default-template.ts`.

## ИИ-агенты

Агент — участник пространства на базе языковой модели (`User.kind = AGENT`). Подключается в «Настройки → Агенты»: провайдер (Anthropic, OpenAI, Google Gemini или любой OpenAI-совместимый сервис с адресом API), модель, **ключ клиента**, инструкция и роль. Ключ хранится зашифрованным (AES-256-GCM, `AGENT_SECRET_KEY`) и обратно не показывается. Агент занимает место тарифа, как сотрудник, но войти в систему не может.

Агент реагирует, когда его назначают на карточку, упоминают через `@` или пишут сообщение в карточке, где он исполнитель. Он видит карточку, доску, команду и последние 20 сообщений и работает через инструменты: написать сообщение (с упоминаниями), перенести карточку, изменить поля, добавить и отметить подзадачи, найти карточки. Удалять, менять исполнителей, настройки и оплату он не может. Ошибки (например, неверный ключ) агент пишет в карточку, история запусков с токенами — в настройках.

Агенты доступны только на тарифе Business: ниже него новых подключить нельзя, подключённые остаются в команде, но не работают.

Расход токенов (вход и выход) пишется по каждому запуску и показан на странице «Агенты»: по агенту за сегодня и 30 дней и общий итог. Оплата самих токенов идёт с ключа клиента у провайдера.

Ограничения: 8 шагов на запуск, 6 запусков в час на карточку, 300 в сутки на пространство (`AGENT_RUNS_PER_DAY`), не работает в режиме чтения, без места и в выключенном виде. Адрес API должен быть публичным и по https (запрет на внутренние сети).

## Публичный сайт: русский и английский

Лендинг и тарифы выходят на двух языках: русский в корне (`/`, `/pricing`), английский под `/en` и `/en/pricing`. Язык задан адресом, страницы рендерятся на сервере (для поисковиков), в метаданных есть `hreflang`, в `sitemap.xml` обе версии, у каждой своя OG-картинка. Переключатель RU/EN в шапке ведёт на «близнеца» страницы, ссылки регистрации и входа с английского сайта несут `?lang=en`.

Цены на английском сайте показываются в долларах (Pro $14.99, Business $29.99 за пользователя в месяц, год = 10 месяцев, константы `USD_MONTHLY` в `apps/web/src/lib/marketing.ts`). Это только витрина: оплата в приложении идёт в рублях.

Юридические страницы (оферта, политика, согласие, реквизиты) и PDF-счета остаются на русском.

Тексты сайта лежат в общем каталоге под ключами `mk.*`, вызываются через `makeTr(locale)` (явный язык, без чтения браузера).

## API, вебхуки, календарь и горячие клавиши

- **Токены API** (Настройки → Интеграции): личные, действуют с правами владельца, хранится только хеш-запись `ApiToken` (токен — подписанный JWT с `tok`, показывается один раз). `Authorization: Bearer <токен>` работает на всех методах; управлять токенами по токену нельзя. Отозвать — удалить запись, отключённый сотрудник теряет и токены.
- **Документация** — публичная страница `/docs/api` и `/en/docs/api` (`components/marketing/api-docs.tsx`): доступ, быстрый старт, список стабильных методов, вебхуки, календарь.
- **Вебхуки** (право `webhooks.manage`, `src/webhooks/`): события `card.created|updated|moved|deleted`, `comment.created`; `CardsService` вызывает `WebhooksService.emit` (в том числе из массовых действий). Тело — JSON, заголовки `X-Plano-Event`, `X-Plano-Timestamp`, `X-Plano-Signature: sha256=HMAC(секрет, "время.тело")`. Секрет хранится запечатанным (`agents/secret.ts`), виден один раз. Адрес — публичный https (`assertPublicUrl`, в разработке `AGENTS_ALLOW_PRIVATE_URLS=1`), до 10 на пространство. Таймаут 8 с, до трёх попыток (через 5 и 30 с), последние 50 отправок на вебхук хранятся в `WebhookDelivery`.
  Доставка идёт в процессе API без очереди: перезапуск прерывает повторы.
- **Календарь iCal**: профиль → «Календарь» выдаёт секретную ссылку `/calendar/<токен>/plano.ics` (поле `User.icalToken`, замена — «Создать новую ссылку»). В ленте незавершённые карточки пользователя со сроком (весь день; со `startDate` — отрезок), без карточек в последней колонке доски.
- **Метки вместо типов**: новое пространство получает метки «Ошибка», «Фича», «Улучшение» (`DEFAULT_LABELS`).
- **Палитра команд и горячие клавиши** (`components/command-palette.tsx`, `lib/palette.ts`): `⌘K`/`Ctrl+K` или `/` — разделы, проекты, действия и поиск карточек; `G` и затем `D`/`P`/`T`/`R`/`S`/`U` — переход; `?` — список; `[` — боковое меню. Клавиши не срабатывают при вводе в поле.
