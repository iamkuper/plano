# Plano

Канбан-доски задач для команд. Мультитенантный: у каждой компании своё рабочее пространство.

## Стек

- `apps/api`: NestJS 10 + Prisma 5 + PostgreSQL, порт 3101
- `apps/web`: Next.js 14 (App Router) + Tailwind 3, порт 3100
- `packages/shared`: общие типы, права (`PERMISSIONS`, `can`), константы — собирается в `dist`

## Запуск

```bash
./scripts/cloud-setup.sh   # зависимости, .env, Postgres на :5433, миграции, тестовые пользователи
pnpm api:dev               # http://localhost:3101
pnpm web:dev               # http://localhost:3100
```

Postgres встроенный (`embedded-postgres`, данные в `apps/api/.pgdata`), Docker не нужен.
Остановить: `pnpm db:down`. Тестовые пользователи и пароли — в `apps/api/.env.example`.
Новое рабочее пространство создаётся на `/register`: компания + её первый администратор.

## Модель

Проект → Доска → Колонки (последняя = «Готово») → Карточки (чек-лист, сообщения,
вложения, учёт времени, история). Повторяющиеся задачи создают карточки по расписанию.
Роли: встроенный «Администратор» (может всё) и свои роли с набором прав
(Настройки → Права).

## Мультитенантность

Общая база, у верхних сущностей (`User`, `Project`, `Card`, `Template`, `Role`) есть `workspaceId`,
остальное достаётся через них. Изоляция — в `apps/api/src/prisma/tenant.ts`: `PrismaService` (его
получают все сервисы) ограничивает любой запрос рабочим пространством текущего пользователя и падает
без контекста. Для логина, планировщика повторяющихся задач и подписанных ссылок на файлы есть
`SystemPrismaService` без ограничений. Проверка изоляции на запущенном API: `node apps/api/test/isolation.mjs`.
Почта пользователя уникальна глобально: аккаунт принадлежит одному пространству.
